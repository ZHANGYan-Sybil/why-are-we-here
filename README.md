# Why Are We Here?

## Introduction
AI is changing what it means to learn programming as a designer. A system can now turn a simple sentence into working code, making it possible to create things that once required much more technical knowledge. As someone without a programming background, this makes the question especially relevant to me: if AI can increasingly write the code, what is left for me to learn?

I have come to think that the answer is not about competing with AI at writing code. It is about understanding enough of programming to control, question, and shape what AI produces. Without that understanding, I can ask for things, but I may not know how to specify them precisely, recognise when something has gone wrong, or connect a generated solution to the larger system of my work. For me, learning programming is therefore less about becoming a programmer and more about becoming a designer who can work with computational systems without losing creative control.

## Why Programming Still Matters
### Precise Creative Control
AI can generate visual outcomes from broad descriptions, but describing an idea is not the same as specifying how it should work. Understanding code allows creators to see how parameters and rules shape an outcome, and therefore make more deliberate creative decisions. My experience with the Schotter exercise showed me that changing a few parameters could significantly alter the balance between order and disorder. Programming therefore gives me a way to understand and control a generative system rather than simply accepting what it produces.

### Critical Judgement
Programming is also about reading, not just writing. AI-generated code may run successfully while still producing the wrong result. The 3×5 grid exercise demonstrated this through a simple list-reference error that was not immediately obvious from the code itself. Understanding how the code worked allowed me to identify why the result was wrong. If AI increasingly writes the code, my ability to evaluate what it produces becomes more important, not less.

### Creative Meaning
Finally, programming connects technical processes with creative intention. In the tidal-stream visualisation, for example, the code could generate and manipulate forms, but the decision to represent tidal data through concentric rings was fundamentally a design decision. AI can increasingly suggest and implement creative solutions, but I still need to judge whether they communicate what I intend. Programming helps me understand the relationship between intention, logic, and outcome.

## What This Means for Me
My own background makes this question particularly relevant to me. I studied urban design as an undergraduate and had almost no programming experience before taking this course. When AI tools began to become more common, I often found myself impressed by the sophisticated and visually ambitious things other people were making with them. At the same time, I realised that I was mostly using AI for relatively simple tasks, such as writing and editing text. Whenever I tried to use it for something more complex, I often felt that I quickly lost control of the process.

One example was a project I wanted to develop around guitar music. My idea was to take the information from guitar tablature and translate it into colours and coordinates, creating a visualisation in which the movement of the music could be seen rather than heard. In theory, this seemed like exactly the kind of problem AI should be able to help with. In practice, however, I struggled at almost every stage. I knew that there was a guitar-related library on GitHub that could help me process the data, but I did not know how to install and use it locally. I also found it difficult to describe my idea precisely enough for AI to understand what I actually wanted. When the generated code produced errors, or when the visual result looked completely different from what I had imagined, I often did not know where to start fixing it. I realised that asking AI for a result is not the same as knowing how to build one. I needed to understand the structure of the code, know how different parts connected to each other, and at a basic level, even know how to manage and upload the code I was working with.

I experienced something similar when I started learning the Blueprint system in Unreal Engine 5. AI could be helpful when I wanted to implement a small and isolated function, but the situation became much more difficult when the problem involved the wider structure of my project. A Blueprint does not exist on its own; it interacts with other Blueprints, levels, functions, variables, and systems. AI could suggest solutions to individual problems, but it did not always have enough context to understand how those solutions would affect the rest of my project. This often left me feeling frustrated and powerless, because I was waiting for AI to understand a system that I did not yet understand well enough myself.

Dylan Beattie describes code not simply as a technical tool, but as something that can itself be expressive (Beattie, 2020). I do not need to learn programming because AI cannot do these things. I need to learn it because I want to be able to work with AI without losing control of the process. The more capable AI becomes, the more important it may be for me to understand the systems I am asking it to operate within. I do not need to become a professional programmer, but I do need enough programming literacy to install and organise tools, understand the structure of a system, communicate my intentions precisely, diagnose problems, and decide whether an AI-generated solution actually moves my work in the direction I want.
